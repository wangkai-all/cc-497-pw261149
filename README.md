# 财务余额差异分析系统

比较**总账（GL）、明细（DETAIL）、结算（SETTLEMENT）、调整（ADJUSTMENT）**四张表，
按 **账期 → 组织 → 币种 → 科目** 逐层钻取差异，自动诊断候选原因并挂载证据，
修复建议以**新版本**方式生效（原始余额永远不可改写），关账后只能走**受控更正**。

## 快速开始

```bash
python3 -m venv .venv
.venv/bin/pip install fastapi uvicorn pytest httpx
.venv/bin/python -m uvicorn app.main:app --app-dir backend --port 8077
# 打开 http://localhost:8077
```

首次启动自动建库并装载演示数据（3 个账期、3 个组织、2 种币种，植入 6 类典型差异）。
页面右上角可切换操作人（分析员 / 财务经理）与明暗主题，「重置数据」可还原演示场景。

运行测试：

```bash
.venv/bin/python -m pytest backend/tests/ -q   # 17 个端到端测试
```

## 平衡式与差异定义

余额语义为**当期发生额**。对每个 (账期, 组织, 币种, 科目) 键：

```
应平金额 = 明细 + 调整          （调整表金额应已反映在总账与结算中）
总账差   = 总账 − 应平金额
结算差   = 结算 − 应平金额
差异额   = max(|总账差|, |结算差|)   ≠ 0 即构成差异
```

## 核心机制

### 1. 版本化余额（不可改写）

`balances` 表只 INSERT 不 UPDATE/DELETE。当前有效余额 = 同一键下 `version` 最大的行。
修复建议应用时插入 `version+1` 的新行并记录来源建议 ID，形成完整版本链；
原始行（v1）永远保持装载时的值。页面「差异详情 → 余额版本链」可直接查看。

### 2. 差异定位：候选原因 + 证据

诊断规则引擎为每条差异生成候选原因（含置信度与可解释金额），证据落到具体分录：

| 规则 | 判定逻辑 | 证据 |
|---|---|---|
| 重复入账 | 同源同凭证号，正数有效条数（扣除红冲）≥ 2，且多计金额解释格差 | 重复分录组 |
| 跨期冲销 | 同一凭证号出现在多个账期 / 冲销链（reversal_of）跨期，金额解释格差 | 跨期分录对 + 各账期开关状态 |
| 结算缺失 | 明细分录按金额对消后仍有剩余，且剩余合计正好等于结算缺口 | 未匹配明细分录 |
| 调整未过账 | 调整表有发生额，且总账缺口恰好等于调整额 | 调整分录 |
| 时间性差异 | 业务日期所属账期 ≠ 入账账期 | 错位分录 |
| 汇率尾差 | 外币且差异 ≤ 0.50（仅在无更具体解释时报告） | 阈值说明 |

候选原因可「确认 / 排除」，全部操作写入审计。

### 3. 修复建议与受控更正

- **开放账期**：建议类型为调整分录 / 红字冲销，创建人可直接应用（全程审计）。
- **关账账期**：任一修复动作落在已关账期间 → 自动变为**受控更正**，
  必须 `提交 → 审批（审批人 ≠ 创建人，双人控制）→ 应用`。
- **应用前验证**（验证失败拒绝应用）：
  - 跨期冲销：同一 (来源, 组织, 币种, 科目) 跨期平移净额必须为 0；
  - 重复入账：重复组仍然存在且未被红冲，冲回金额恰好等于一份；
  - 调整未过账：当前总账缺口仍等于调整额（账面未被其他修复改变）。
- **应用后复核**：自动重算受影响键的格差，归零则差异与建议标记「已验证」；
  跨期修复会同时复核两侧账期的差异。

### 4. 审计

对账运行、诊断、原因确认/排除、建议创建/提交/审批/驳回/应用/验证、
余额新版本、差异豁免、关账——全部写入 `audit_log`（操作人、时间、实体、载荷），
页面「审计记录」可按实体类型过滤。

## 页面

- **差异树**：统计卡片 + 账期→组织→币种→科目四级树表，逐层展开，
  四表金额、应平金额、双向格差、状态一览；点击科目行打开详情抽屉。
- **差异详情**：四表金额对比条形图（零轴居中、直接标值、悬停提示）、
  候选原因与证据分录、修复建议、余额版本链。
- **修复进度**：状态流水线（草稿→提交→审批→应用→验证）+ 建议列表，
  按当前操作人角色启停按钮（如受控更正需非创建人审批）。
- **审计记录**：全量操作流水。

## 代码结构

```
backend/app/
  db.py         # SQLite 模式：版本化余额、分录、差异、原因、建议、审计（追加式）
  reconcile.py  # 对账引擎：当前余额、平衡式格差、差异树
  causes.py     # 诊断规则引擎：候选原因 + 证据
  fixes.py      # 修复建议：生成、状态流转、应用前验证、应用与复核
  seed.py       # 演示数据（植入 6 类差异场景）
  main.py       # FastAPI 路由 + 静态页
backend/tests/test_api.py  # 17 个端到端测试
frontend/       # 原生 SPA：差异树 / 详情抽屉 / 修复进度 / 审计记录
```

## API 摘要

```
POST /api/runs                      执行对账        GET  /api/tree?period=      差异树
GET  /api/differences               差异列表        GET  /api/differences/{id}  详情(原因/证据/建议/版本链)
POST /api/differences/{id}/diagnose 运行诊断        POST /api/differences/{id}/waive  豁免
POST /api/causes/{id}/confirm|reject 确认/排除原因
POST /api/differences/{id}/proposals 生成修复建议   GET  /api/proposals           建议列表
POST /api/proposals/{id}/submit|approve|reject|apply  状态流转
GET  /api/versions                  余额版本链      GET  /api/audit              审计记录
POST /api/periods/{period}/close    关账            POST /api/seed               重置演示数据
```

所有变更类接口通过 `X-User` 请求头识别操作人（`analyst.chen` / `manager.liu`）。
